# Deviation Ledger: F04 — Dashboard & Reporting

**Branch**: `v3-004-dashboard-reporting` | **Date**: 2026-11-09 (revised 2026-11-10) | **Spec**: [spec.md](spec.md)

This ledger documents intentional implementation differences between Celia's production implementation and the prototype reference (`reference/Money Tracker Hi-Fi.dc.html` in `handoff/celia_v3_001.zip`). All items are grounded in the approved feature specification and constitution.

| ID | Area | Hi-Fi Prototype | Celia F04 Implementation | Rationale | Status |
|---|---|---|---|---|---|
| **D1** | Upcoming Commitments card (`src/components/dashboard/upcoming-commitments-card.tsx`) | Prototype hardcodes arbitrary recurring commitments (`Rent · Sep 30 · ₱25,000`, `Car maintenance · Sep 15 · ₱3,500`) in mock data (`HF#L1332`). | Derived dynamically from active F03 Sinking Fund and Goal buckets with target dates (`targetMonth >= selectedMonthKey`) and a defined target amount (`targetAmount > 0`), showing bucket name, formatted due month, and remaining target amount. Displays clean empty state if none exist. | Brief §3.9 and Spec Clarification 2026-11-09 #2 prohibit introducing a separate commitments engine or fabricating mock commitments. | Approved in Spec (2026-11-09) |
| **D2** | Member Filter on Budgets & Savings (`src/server/dashboard-read.ts`, `src/components/dashboard/categories-breakdown-table.tsx`) | Prototype arbitrarily halved category budgets (`c.budget * 0.5`) when filtering by member (`HF#L939, L1037`). | Member filter scopes actual transactions only (Income, Expenses, and Category spending table actuals). Household-level budget and savings components (Savings Buffer hero, Burn Rate gauge, and Budget vs Actual line) show household totals with clear indicators that budgets and buffers are household-wide. | Brief §3.2, §3.8 and Spec Clarification 2026-11-09 #3 explicitly state that household budgets and savings must not be arbitrarily distributed among members. | Approved in Spec (2026-11-09) |
| **D3** | Categories Table `↺` Rollover Column (`src/components/dashboard/categories-breakdown-table.tsx`) | Prototype mock model displayed a `↺` column with arbitrary rollover balances carried from previous periods (`HF#L1012`). | Displays current-period unspent allocation (`budget − spent` when positive, or `—` when zero/overspent) purely as an informational remaining amount without rolling balances over into future months. | Brief §3.4 and Spec Clarification 2026-11-09 #5 confirm Celia has no automated multi-month budget rollover engine. | Approved in Spec (2026-11-09) |
| **D4** | Unbudgeted & Zero-Data Empty States (`src/components/dashboard/*`, `src/app/(shell)/(dashboard)/page.tsx`) | Prototype assumes pre-seeded mock database (`data/seed.json`) with an applied budget model and transactions for all months (`HF#L830–L1360`). | Implements explicit, accessible empty states across all cards when opening on a clean first-run database, or viewing a month without an applied plan (`"—"` center gauge with `"No plan applied"` and `"Zero budget · ₱0 spent"`). | Constitution Principle III & XII require explicit, graceful empty states for first-run installations without thrown errors or blank white boxes. | Approved in Spec (2026-11-09) |
| **D5** | Accessible Status Amber / Warning Text Color (`src/components/dashboard/*`) | Prototype uses `#b9822c` for amber/warning text on white cards (`HF#L1052, L1108`). Contrast ratio against `#ffffff` is 3.1:1, failing WCAG AA. | Replaces `#b9822c` text with `#8a6516` (contrast ratio 4.9:1 $\ge$ 4.5:1). Visual indicators (gauges, dots, bars) retain prototype amber hue `#d3a13f` / `#b9822c`. | Constitution Principle XIII mandates WCAG AA text contrast ($\ge$ 4.5:1) across all text elements. | Approved in Spec (2026-11-09) |
| **D6** | Direct Transaction Entry on Dashboard (`src/components/dashboard/dashboard-header.tsx`, `src/components/entries/entry-modal.tsx`) | Prototype includes `+ Add entry` CTA on the dashboard header (`HF#L78`) but provides no embedded save implementation. | Reuses existing F02 `EntryModal` and `POST /api/entries` API endpoint, passing complete `modalCategories` and `modalMembers` records, displaying a toast upon success and refreshing dashboard data via `router.refresh()`. | F04 Brief §3.1 and User Story 6 require actionable transaction entry directly from the dashboard. | Approved in Spec (2026-11-09) |
| **D7** | Desktop Layout Responsiveness (`src/components/dashboard/dashboard-screen.tsx`) | Prototype hardcodes fixed widths (`1440px`, e.g. `HF#L50–L205`). | Uses CSS Grid and Tailwind flexbox with explicit breakpoints for 1100px, 1280px, and 1440px desktop viewports, eliminating horizontal scroll at $\ge$1100px width. | Constitution Principle XIII mandates responsive desktop layouts from 1100px to 1440px. | Approved in Spec (2026-11-09) |
| **D8** | Link-Only "Household only" Filter View on `/entries` (`src/components/entries/entries-header.tsx`, `src/components/entries/summary-chips.tsx`) | F02 owner dropdown has `"Household"` (`id: "all"`, meaning all members / everyone) and active members, with no Household-only option. | When navigating via dashboard drill-down with `owner=household`, `/entries` renders the owner chip label as `"Household only ▾"` (clearly distinct from `"Household ▾"` = everyone), filters entries to `owner_member_id IS NULL`, and suppresses the `"0 own · ₱X shared"` summary chips subtitle to display only the total shared amount. Selecting any other option in the dropdown transitions back to F02's standard filter modes. | Enables exact drill-down figure matching for Household-owned category spending without modifying F02's persistent dropdown options or altering `filterEntries`. | Approved in Spec (2026-11-10) |
