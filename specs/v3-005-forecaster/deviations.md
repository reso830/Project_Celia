# Deviation Ledger: F05 — Forecaster

**Branch**: `v3-005-forecaster` | **Date**: 2026-11-18 (revised Req-Review 2026-11-18) | **Spec**: [spec.md](spec.md)

This ledger documents intentional implementation differences between Celia's production implementation and the prototype reference (`reference/Money Tracker Hi-Fi.dc.html` in `handoff/celia_v3_001.zip`) or initial feature brief (`docs/features/v3-005-forecaster.md`). All items are grounded in the approved feature specification, requirements review, and project constitution.

| ID | Area | Hi-Fi Prototype / Brief | Celia F05 Implementation | Rationale | Status |
|---|---|---|---|---|---|
| **D1** | Accessible Status Amber Color (`src/components/forecaster/*`) | Prototype uses `#b9822c` for funded nudge status text on white cards (`HF#L1206`). Contrast ratio against `#ffffff` is 3.1:1, failing WCAG AA. | Replaces `#b9822c` text with `#8a6516` (contrast ratio 4.9:1 $\ge$ 4.5:1 against `#ffffff` and `#fdf9f0`). Visual bar indicators retain prototype amber hue `#d3a13f`. | Constitution Principle XIII mandates WCAG AA text contrast ($\ge$ 4.5:1) across all text elements. | Approved in Req-Review (2026-11-18) |
| **D2** | Stepper-Only Nudge Control (`src/components/forecaster/budget-nudges-card.tsx`) | Prototype markup has drag-handle knob (`HF#L432`) with inline script click step handlers (`HF#L1210`). | Interactive adjustment is handled exclusively via accessible `−` and `+` `<button>` elements with `aria-label`. The slider track and knob act as visual progress indicators. Writes are dispatched via a sequential per-row queue with interim failure continuity (newer queued edits stay visible and are dispatched next). | Eliminates fragile mouse-drag state sync across browsers, prevents race conditions, and ensures full keyboard accessibility. | Approved in Req-Review (2026-11-18) |
| **D3** | Left Column Desktop Width (`src/components/forecaster/forecaster-screen.tsx`) | Prototype grid uses `minmax(260px, 320px) minmax(0, 1fr)` (`HF#L405`). Initial plan drafted `280px–340px`. | Uses the canonical prototype column width `minmax(260px, 320px) minmax(0, 1fr)` on desktop viewports ($\ge 1100\text{px}$). | Aligns with the prototype visual source of truth (Constitution Principle III). | Approved in Req-Review (2026-11-18) |
| **D4** | Dynamic Scenarios & Pinned Table Column (`src/components/forecaster/scenario-comparison-table.tsx`) | Prototype hardcoded a fixed 4-column comparison table (`HF#L472-L486`). | Comparison table dynamically renders columns for Baseline and all active alternative scenarios inside an `overflow-x-auto` container with the metric label column pinned (`sticky left-0 bg-white`). | Supports arbitrary user-created scenarios without breaking layout or causing window horizontal scrolling. | Approved in Req-Review (2026-11-18) |
| **D5** | Baseline Scenario Invariant Protection (`src/server/forecaster-store.ts`, `src/components/forecaster/what-changes-card.tsx`) | Prototype baseline object was a static mock item in an in-memory array (`HF#L652`). | Baseline scenario row is created by Migration 4, preserved by `clearAllData`, and protected against mutations (rename, draw, events, nudges, duplicate, delete), returning 409 `invalid_state`. The `+ add event` CTA is hidden on baseline. | Protects financial baseline integrity (Constitution Principle IV & V). | Approved in Req-Review (2026-11-18) |
| **D6** | No Applied Plan Empty State (`src/components/forecaster/forecaster-screen.tsx`) | Prototype assumed a pre-seeded mock dataset with an applied budget model for all months (`HF#L640`). | If the current calendar month has no row in `monthly_budget_plans`, renders an accessible empty state: `No budget applied for {Month YYYY}.` with an actionable link to `/models`. Does not fall back to older months. | Constitution Principle III & XII require explicit, graceful empty states for unconfigured or first-run environments. | Approved in Req-Review (2026-11-18) |
| **D7** | Flat Baseline Chart Outlook Bars (`src/domain/forecaster-calculations.ts`) | Prototype multiplied baseline monthly unallocated funds by an artificial growth trend: `mUnalloc * (1 + i * 0.004)` (`HF#L1213`). | Forecast baseline bars are flat across all 24 months ($M_0$ through $M_{23}$) matching the applied monthly plan's unallocated amount. Positive bars are sized via `heightRatio / zeroRuleRatio = U_0 / domainHi` to meet the baseline polyline at $U_0$ exactly. Bars extend downwards below the zero rule line if negative (`isNegative = true`). | Avoids ungrounded speculative growth assumptions without supporting financial data (Brief §2, §3.1). | Approved in Req-Review (2026-11-18) |
| **D8** | Event Types & Buffer Draw Scope (`src/domain/forecaster.ts`, `src/components/forecaster/event-modal.tsx`) | Brief §3.5 listed one-time events alongside recurring events. | Event types are strictly `financed purchase`, `recurring`, and `seasonal`. One-time capital draws are modeled exclusively via the scenario's `draw_amount`. Events are flat monthly costs ($> 0$). | Eliminates double-counting and separates capital reserves draws from monthly operating cash flow (Constitution Principle IV). | Approved in Req-Review (2026-11-18) |
| **D9** | Nudge Storage as Signed Delta (`src/server/db/migrations.ts`, `src/domain/forecaster.ts`) | Prototype/Initial schema stored `adjusted_amount` and `freed_amount`. | Stores a single signed integer `delta_amount` in centavos. Negative indicates spending reduction (frees money). `adjusted` and `freed` amounts are derived dynamically. | Eliminates denormalized mutable redundancy; keeps database schema minimal and tamper-proof. | Approved in Req-Review (2026-11-18) |
| **D10** | Scenario Palette Curation & Database Schema (`src/domain/forecaster.ts`, `src/components/forecaster/scenario-modal.tsx`) | Prototype had no scenario creation modal and no palette picker; it hardcoded styles only for baseline (`#3a4145`) and scenarios A (`#2f7d78`), B (`#7c6f9a`), and C (`#a17c3f`). | Introduces a curated 5-option palette (`teal #2f7d78`, `purple #7c6f9a`, `gold #a17c3f`, `blue #2563eb`, `slate #7d8ba8`) for user-created scenarios. `blue` and `slate` are new additions grounded in Celia's design tokens (e.g. category color `#7d8ba8` for slate, ensuring clear visual distinction from baseline `#3a4145`). Scenarios store only `palette_key` in SQLite; hex colors are mapped exclusively in the UI layer. Baseline retains fixed `#3a4145` styling. | Enables user creation of custom alternative scenarios (US5) while keeping the database schema normalized and preventing hex color duplication in domain models (Constitution Principle VIII & XIV). | Approved in Req-Review (2026-11-18) |
| **D11** | Runway Precedence Rule (`src/domain/forecaster-calculations.ts`) | Underspecified behavior when expenses are zero and buffer is overdrawn. | Overdrawn buffer ($\le 0$) always takes precedence over zero expenses, yielding `0.0 mo` and `Risky buffer`. Zero expenses with positive buffer yields `null` (`—`) with verdict from cash flow alone. | Eliminates logical conflict where an overdrawn buffer could incorrectly report "Comfortable". | Approved in Req-Review (2026-11-18) |
| **D12** | Omission of Brief Non-Goals (`specs/v3-005-forecaster/spec.md`) | Brief mentioned selectable horizons, income adjustments/events, temporary toggles, per-month detail table, AI insights, and actuals overlay. | These features are formally categorized as Non-goals. AC2 is met by clearly labelling all figures as projected. AC11 is met via visual deficit indicators (red unallocated, line dipping below zero). | Scopes F05 strictly to deterministic, actionable household forecasting without speculative features. | Approved in Req-Review (2026-11-18) |
